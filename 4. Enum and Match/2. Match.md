# Match
Rust has an extremely powerful control flow construct called `match` that allows you to compare a value against a series of patterns and then execute code based on which pattern matches. Patterns can be made up of values, variable names, wildcards, and many other things  

##### Example:
```
enum Day {
    Monday,
    Tuesday,
    Wednesday,
    Thursday,
    Friday,
    Saturday,
    Sunday,
}

fn main() {
    let today = day_number(Day::Friday);
    println!("Day number: {today}");
}

fn day_number(day: Day) -> u8 {
    match day {
        Day::Monday => 1,    ────────────┐
        Day::Tuesday => 2,               |
        Day::Wednesday => 3,             |
        Day::Thursday => 4,              | Each one is 
        Day::Friday => 5,                | called a match arm
        Day::Saturday => 6,              |
        Day::Sunday => 7,    ────────────┘
    }
}
```
* **match light** → value we want to check
* **Light::Red** → pattern
* **=>** → separates the pattern from the code

Rust checks the patterns one by one. When it finds a match, it runs that code.  

**Simple formula:**  
match = check value → find matching pattern → run code

### match Arm with Multiple Lines
```
fn day_number(day: Day) -> u8 {
    match day {
        // Multiple lines → use curly braces {}
        Day::Monday => {
            println!("Monday");

            // The last expression becomes the result of the block.
            // So this match arm returns 1.
            1
        }

        // Short code → {} not needed
        Day::Tuesday => 2,
        Day::Wednesday => 3,
        Day::Thursday => 4,
        Day::Friday => 5,
        Day::Saturday => 6,
        Day::Sunday => 7,
    }
}
```

### Patterns That Bind to Values
A `match` pattern can take a value from inside an enum variant and store it in a variable.
```
enum Day {
    Monday(String), // Monday can store a String value
    Tuesday,
    Wednesday,
    Thursday,
    Friday,
    Saturday,
    Sunday,
}

fn main() {
    // Put a value inside Monday
    day_number(Day::Monday(String::from("Start of the week")));
}

fn day_number(day: Day) {
    match day {
        // `message` gets the value stored inside Monday.
        Day::Monday(message) => println!("Monday: {message}"),
        Day::Tuesday => println!("Tuesday"),
        Day::Wednesday => println!("Wednesday"),
        Day::Thursday => println!("Thursday"),
        Day::Friday => println!("Friday"),
        Day::Saturday => println!("Saturday"),
        Day::Sunday => println!("Sunday"),
    }
}
```

### `Option<T>` with `match`
We already know what `Option<T>` is at enum chapter. Now let's see how `match` can be used to handle `Some` and `None` (two variant of `Option` enum).
```
fn main() {
    add_one(Some(5));
    add_one(None);
}

fn add_one(x: Option<i32>) {
    match x {
        None => println!("Empty"),
        Some(x) => {
            let r = x + 1;
            println!("result = {r}");
        }
    }
}
```
* `match` checks whether `x` is `Some(value)` or `None`, and then executes the appropriate code.

### `match` Must Cover All Possibilities
In Rust, `match` must handle every possible case. For example, `Option<i32>` has two possible cases:
```
Some(value)
None
```
So if we write:
```
fn add_one(x: Option<i32>) {
    match x {
        Some(x) => {
            let r = x + 1;
            println!("result = {r}");
        }
    }
}
```
This gives an error because we handled `Some`, but forgot `None`. 
#### Another example: traffic light example
```
enum Light {
    Red,
    Yellow,
    Green,
}

fn main() {
    let light = Light::Red;

    match light {
        Light::Red => println!("Stop"),
        Light::Yellow => println!("Get ready"),
        Light::Green => println!("Go"),
    }
}
```
Here Light has 3 possible variants:
```
Red
Yellow
Green
```
So match must handle all 3. If we forget one?
```
match light {
    Light::Red => println!("Stop"),
    Light::Green => println!("Go"),
}
```
Rust gives an error because:
```
Yellow not handled
```
**Rust basically says:**
  ```
  You handled Red and Green, but what should I do if the light is Yellow?
  ```

### Catch-All Patterns and `_`
If some values are not handled in match, we can use a catch-all pattern to handle them.
#### 1) Using a variable as catch-all
```
fn main() {
    let temperature = 30;

    match temperature {
        0 => println!("Freezing point"),
        100 => println!("Boiling point"),

        // Here we use the variable `other` as a catch-all
        // that catches any value not matched above.
        // and we can use that value in our logic
        other => println!("Temperature is {other}°C"),
    }
}
```
#### 2) Using `_` as catch-all
```
fn main() {
    let temperature = 30;

    match temperature {
        0 => println!("Freezing point"),
        100 => println!("Boiling point"),

        // If we don't need to use the value, use _
        _ => println!("Normal temperature"),
    }
}
```
#### Why is the catch-all pattern written at the end?
```
match temperature {
    _ => println!("Some temperature"),
    0 => println!("Freezing point"), // ❌ unreachable
}
```
`_` matches everything, so Rust can never reach 0. That's why we always put the catch-all pattern (`other` or `_`) at the end.
