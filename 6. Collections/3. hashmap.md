# Hash Maps

## What is a HashMap?
A HashMap stores data as **key-value pairs**. It lets you find a value using its key instead of an index.
* **Key (K):** Used to find data.
* **Value (V):** The data associated with the key.

### Creating a HashMap
```rust
// creates an empty hash map
// mut is needed because we modify the hash map.
let mut scores = HashMap::new(); 

scores.insert("Alice", 20);  // adds a key-value pair.
scores.insert("Bob", 10);    // adds a key-value pair.
```

### Accessing Values
Use `get()` to retrieve a value by its key.
```rust
let mut scores = HashMap::new();

scores.insert(String::from("Alice"), 20);
scores.insert(String::from("Bob"), 10);

let name = String::from("Alice");
let score = scores.get(&name).copied().unwrap_or(0);
```
* `get(&team_name)` — returns `Option<&i32>`. It returns `Some(&10)` if the key exists, or `None` if it doesn't.
* `copied()` — converts `Option<&i32>` into `Option<i32>` by copying the integer.
* `unwrap_or(0)` — returns the value if present; otherwise, returns 0.
#### Why &name?
Because `get()` borrows the key rather than taking ownership of it.
```rust
let score = scores.get("Alice").copied().unwrap_or(0);
                          |
                          |
                        this is &str type
```
"Alice" is already an &str, so get() borrows it for lookup without taking ownership.  

**Remember:** `get()` borrows the lookup key whether you pass a string literal (`&str`) or a reference to a `String` (`&String`).

#### Iterating Over a HashMap
```rust
let mut scores = HashMap::new();

scores.insert(String::from("Alice"), 20);
scores.insert(String::from("Bob"), 10);

// The loop visits each key-value pair one by one.
for (key, value) in &scores {
    println!("{key}: {value}");
}
```
* `&scores` borrows the HashMap without taking ownership. When you borrow a HashMap using `&`, its keys and values are also accessed through references by default.
* `key` contains a reference to the key (`&String`).
* `value` contains a reference to the associated value (`&i32`).

### Managing Ownership in Hash Maps
When inserting data into a HashMap, Rust handles ownership in two ways:
1) **Copy types (`i32`, `bool`, etc.):** Values are copied into the HashMap. The original variable can still be used.
   ```rust
    let field_name = 1;
    let field_value = 100;

    let mut map = HashMap::new();

    map.insert(field_name, field_value);

    // Original variables are still usable
    println!("Key: {}", field_name);
    println!("Value: {}", field_value);
   ```
2) **Owned types (`String`, etc.):** Ownership moves into the HashMap. The original variable cannot be used anymore.

#### Example
```rust
let field_name = String::from("Favorite color");
let field_value = String::from("Blue");

let mut map = HashMap::new();

map.insert(field_name, field_value);

// field_name and field_value cannot be used here.
// Their ownership has moved into the HashMap.
```
**What happens?**
* `field_name` ownership moves into the HashMap as the key.
* `field_value` ownership moves into the HashMap as the value.
* The HashMap now owns both String values.

#### What if we want to keep ownership?
Use references (`&`) instead of moving the values:
```rust
map.insert(&field_name, &field_value);
```
Now the HashMap borrows the values instead of owning them.  

**Important:** The original values must exist as long as the HashMap uses their references.

### Updating a HashMap
A HashMap allows multiple key-value pairs, but each unique key can have only one value at a time. Different keys can have the same value.   

When updating a HashMap, there are three common operations:

#### 1) Overwriting a Value
If you insert the same key with a different value, the old value is replaced.
```rust
let mut scores = HashMap::new();

scores.insert(String::from("Blue"), 10);
scores.insert(String::from("Blue"), 20);

println!("{scores:?}");
```
The old value 10 is replaced with 20.

#### 2) Adding a Value Only If the Key Doesn't Exist
```rust
let mut scores = HashMap::new();

scores.insert(String::from("Blue"), 10);

scores.entry(String::from("Red")).or_insert(15);
scores.entry(String::from("Blue")).or_insert(20);

println!("{scores:?}");
```
* `entry(key)` checks whether the key exists.
* `or_insert(value)` inserts the value only if the key doesn't exist.
* If the key already exists, its old value remains unchanged.

#### 3) Updating a Value Based on Its Old Value
We can use a HashMap to count how many times each word appears in a text.
```rust
let text = "hello world wonderful world";
let mut map = HashMap::new();
for word in text.split_whitespace() {
    let count = map.entry(word).or_insert(0);
    *count += 1;
}
println!("{map:?}");
```
**Explain:**  
1. Initially, the HashMap is empty
2. `split_whitespace()` splits the text into individual words based on whitespac
3. First iteration: `hello`
    * `hello` doesn't exist, so `or_insert(0)` inserts it with value 0.
    * `count` gets a mutable reference to that value.
    * `*count += 1` changes its value to 1.
    ```rust
    {"hello": 1}
    ```
4. Second iteration: `world`
    * `world` doesn't exist, so it gets inserted with 0, then increased to 1.
    ```rust
    {"hello": 1, "world": 1}
    ```
5. Third iteration: `wonderful`
    * It doesn't exist, so it is inserted with 0, then increased to 1.
    ```rust
    {"hello": 1, "world": 1, "wonderful": 1}
    ```
6. Fourth iteration: `world`  
    This time `world` already exists with value 1.
    * `or_insert(0)` does not replace the existing value.
    * `count` gets a mutable reference to the existing value 1.
    * `*count += 1` increases it to 2.
    ```rust
    {"hello": 1, "world": 2, "wonderful": 1}
    ```

**Why `*count`?**  
* `or_insert()` returns a mutable reference (`&mut V`), not the actual value.
* The `*` (**dereference operator**) lets us access and modify the actual value.
* The mutable reference goes out of scope at the end of each loop iteration.
